## Procedimiento (skill cargado bajo demanda)
# Jira work-item planning

## Before drafting
1. Load the approved Jira project context, issue taxonomy, workflow, required fields, Definition of Ready/Done and naming conventions. If absent, state that the ticket is only a generic draft.
2. Confirm requested outcome, stakeholder, scope, dependencies, priority rationale and target milestone.
3. Decompose work by independently verifiable outcomes, not arbitrary code layers.

## Drafting rules
- Epic: outcome and broad capability.
- Story: user/business value and acceptance criteria.
- Task: technical work with clear deliverable.
- Bug: observed vs expected behavior, reproducibility, impact and evidence.
- Subtask: bounded implementation or verification step.

Include: summary, context, scope, acceptance criteria, dependencies, risks, test expectations, documentation impact and source links.

## Safety
Drafting text is allowed in the approved workspace. Creating, editing, transitioning, assigning, commenting or linking Jira issues is an external side effect and requires explicit user approval, approved credentials and project permissions. Do not invent project keys, required fields, issue types or workflow states.
